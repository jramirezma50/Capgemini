📚 Entendiendo Terraform

¿Qué es Terraform?

Terraform es una herramienta de Infrastructure as Code (IaC) creada por HashiCorp. Permite definir, previsualizar y gestionar tu infraestructura en la nube de manera declarativa.

En lugar de hacer clic en la consola de AWS, escribes código que describe la infraestructura que quieres, y Terraform se encarga de crearla, modificarla o destruirla automáticamente.

📝 Declarativo (No Imperativo)

Declarativo: "Quiero 3 instancias EC2"

Imperativo: "Crea instancia 1, luego 2, luego 3"

Terraform es declarativo, más simple y seguro

🔄 Idempotencia

Ejecutar el mismo código 10 veces da el mismo resultado

Terraform verifica el estado actual y solo hace cambios necesarios

📦 Proveedores (Providers)

Terraform soporta múltiples proveedores:

AWS, Azure, GCP, Kubernetes, Docker, etc.

Misma sintaxis para cualquier proveedor

💾 State File (archivo de estado)

Terraform guarda el estado en un archivo (.tfstate)

Contiene info de recursos creados

Se usa para detectar cambios y hacer updates

Estructura de Archivos Terraform

# 1. provider.tf - Configuración del proveedor
terraform {
  required_providers {
    aws = {
      source = "hashicorp/aws"
      version = "~> 5.0"
    }
  }
}

provider "aws" {
  region = var.aws_region
}
# 2. variables.tf - Define variables de entrada
variable "vpc_cidr" {
  description = "CIDR block para la VPC"
  type        = string
  default     = "10.0.0.0/16"
}

variable "instance_count" {
  description = "Número de instancias EC2"
  type        = number
  default     = 2
}
# 3. main.tf - Define recursos
resource "aws_vpc" "main" {
  cidr_block = var.vpc_cidr
  tags = {
    Name = "capgemini-vpc"
  }
}

resource "aws_instance" "web" {
  count          = var.instance_count
  ami            = "ami-0c55b159cbfafe1f0"
  instance_type = "t3.micro"
}
# 4. outputs.tf - Define valores de salida
output "vpc_id" {
  value        = aws_vpc.main.id
  description = "ID de la VPC creada"
}

output "instance_ips" {
  value        = aws_instance.web[*].public_ip
  description = "IPs públicas de las instancias"
}

🐳 Entendiendo Docker

¿Qué es Docker?

Docker es una plataforma de containerización que empaqueta tu aplicación con todas sus dependencias en un "contenedor" aislado y portátil.

Piénsalo como una caja hermética: tu app funciona igual en tu computadora, en staging, en producción, en cualquier lugar. No hay más "funciona en mi máquina pero no en el servidor".

🏗️ Imagen vs Contenedor

Imagen: Plano/plantilla (como una clase)

Contenedor: Instancia en ejecución (como un objeto)

Construyes la imagen una vez, ejecutas muchos contenedores de ella

📦 Capas (Layers)

Las imágenes se construyen en capas

Cada comando en el Dockerfile es una capa

Docker cachea capas para builds más rápidos

🌐 Aislamiento

Cada contenedor tiene su propio:

Sistema de archivos, red, procesos

No interfieren entre sí

📡 Orquestación con Docker Compose

Ejecuta múltiples contenedores como un sistema

Define servicios, redes, volúmenes en YAML

Un comando para iniciar todo: docker-compose up

Archivo Dockerfile Explicado

# Dockerfile - Receta para construir una imagen
FROM python:3.11-slim               # Imagen base (sistema operativo)

WORKDIR /app                          # Directorio de trabajo en el contenedor

COPY index.html .                       # Copia archivos desde tu máquina al contenedor
COPY styles.css .

EXPOSE 8000                            # Expone puerto 8000

CMD ["python", "-m", "http.server", "8000"]  # Comando a ejecutar al iniciar

Archivo docker-compose.yml Explicado

# docker-compose.yml - Orquesta múltiples contenedores
version: '3.8'

services:
  web:                                    # Nombre del servicio
    build: .                             # Construir desde Dockerfile
    ports:
      - "8000:8000"                   # Puerto local:contenedor
    volumes:
      - ./index.html:/app/index.html    # Sincroniza archivos
    environment:
      - PYTHONUNBUFFERED=1               # Variables de entorno
    restart: unless-stopped             # Reinicia si falla

  team-api:                               # Otro servicio
    image: python:3.11-slim             # Usa imagen existente
    ports:
      - "8001:8001"

networks:                             # Red personalizada
  capgemini-network:
    driver: bridge                      # Permite que los contenedores se comuniquen

Workflow Completo

📝 Paso 1: Desarrollar Localmente

# Ejecutar con Docker Compose en tu máquina
docker-compose up -d

# Visita http://localhost:8000
# Tu app se ejecuta en contenedores aislados

📋 Paso 2: Definir Infraestructura con Terraform

# En main.tf defines la infraestructura
resource "aws_instance" "web" {
  ami            = "ami-0c55b159cbfafe1f0"
  instance_type = "t3.micro"
  key_name      = aws_key_pair.deployer.key_name
  user_data     = file("${path.module}/scripts/user_data.sh")
}

🚀 Paso 3: Crear Infraestructura

# Inicializar Terraform
terraform init

# Ver cambios que se harán
terraform plan -var-file=environments/dev/terraform.tfvars

# Aplicar cambios (crear instancias en AWS)
terraform apply -var-file=environments/dev/terraform.tfvars

📦 Paso 4: Ejecutar Docker en las Instancias

# El script user_data.sh (ejecutado automáticamente) instala:
# - Docker
# - Docker Compose
# - Tu aplicación
# - Inicia los contenedores

# Resultado: Tu app ejecutándose en AWS en contenedores

Ambientes Multi-Tenant

🧪 Development (dev)

  • Instancia: t3.micro
  • Cantidad: 1
  • Costo: Bajo
  • Propósito: Desarrollo y pruebas rápidas

⚙️ Staging

  • Instancia: t3.small
  • Cantidad: 2
  • Costo: Medio
  • Propósito: Pruebas pre-producción

🔒 Production (prod)

  • Instancia: t3.medium
  • Cantidad: 3+
  • Costo: Alto
  • Propósito: Usuarios finales, Alta disponibilidad

⚡ Comandos Útiles

Docker Compose

# Iniciar contenedores en segundo plano
docker-compose up -d

# Ver logs en tiempo real
docker-compose logs -f

# Detener contenedores
docker-compose down

# Listar contenedores corriendo
docker-compose ps

# Ejecutar comando en contenedor
docker-compose exec web bash

Terraform

# Inicializar proyecto Terraform
terraform init

# Validar sintaxis
terraform validate

# Ver plan de cambios
terraform plan

# Aplicar cambios
terraform apply

# Destruir infraestructura
terraform destroy

# Ver estado actual
terraform show

AWS CLI (Verificación)

# Ver identidad conectada
aws sts get-caller-identity

# Listar instancias EC2
aws ec2 describe-instances

# Listar VPCs
aws ec2 describe-vpcs
